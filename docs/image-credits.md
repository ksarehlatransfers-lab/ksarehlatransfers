# Image credits

Every photograph on this site comes from Wikimedia Commons under an open
license. Files were downloaded from `upload.wikimedia.org`, cropped and
re-encoded to WebP, and are served from `public/images` through
`next/image`. License and author data was read from the MediaWiki
`imageinfo` API, not written by hand.

The typed manifest in `lib/site-images.ts` is generated and carries the same
credit data, so attribution travels with each image in code.

## Re-running the pipeline

The pipeline is **in the repository**:
[`scripts/sync-images.mjs`](../scripts/sync-images.mjs), reading
[`scripts/images.manifest.json`](../scripts/images.manifest.json).

```
node scripts/sync-images.mjs
```

To add or replace a photograph, add an entry to the manifest (key, Commons
file name, output file name, target shape, subject and both alt texts) and run
it. It downloads the Commons original, crops it with sharp's attention
strategy, encodes WebP, computes the blur placeholder, reads licence and
author from the MediaWiki `imageinfo` API, writes the credit back into the
manifest, and regenerates both `lib/site-images.ts` and the table above. An
image whose output file already exists is **left alone**, so re-running does
not churn published files. It is idempotent: a second run produces no diff.

It refuses any file whose Commons metadata carries usage restrictions.

**Why this is committed now.** It used to live outside the repository as a
"one-off sourcing tool" — and was then lost, which turned two Batch 2
photographs into a build gate that blocked the batch. Adding a photograph is a
repository operation.

### Known one-time change

The 24 photographs that predate this script kept their files byte-for-byte,
but their inline **blur placeholders were regenerated** and differ from the
lost script's output, because its encoding settings are unknown. The
placeholders are 20-pixel-wide previews shown while the real image loads;
dimensions, files and rendering are unchanged. Future runs are stable.

## Replacing these with commissioned photography

These images are stand-ins chosen because they are openly licensed and
genuinely depict the places named. None of them depict this company's own
vehicles, staff or customers, and none are presented as doing so. When
commissioned or stock-licensed photography is available, drop the new files
into `public/images` under the same names and update
`lib/site-images.ts` — no component changes are needed.
